# PHP2Shell（CVE-2026-109618 / CVE-2026-109619）— longjmp で後片付けが飛ぶと何が壊れるか

実在CVEのケーススタディ。既存の層例（入力検証層の XSS/SQLi/CSRF）とは別の、
**言語ランタイム層のメモリ破壊**の実例として記録する。攻撃手順は書かない。原因の理解が目的。

## 1行で

fatal エラーや OOM の脱出に使う `longjmp()` が通常の制御フローを飛び越え、
**途中までしか進んでいない状態**（カウンタだけ増えた／ポインタだけ残った）を残す。
後続処理がその状態を「正常」と信じて触り、未初期化メモリ読み取り・use-after-free につながる。

## 前提：なぜ longjmp が問題になるか

PHP は fatal エラー／メモリ上限超過を `setjmp`/`longjmp` で処理する。
`longjmp` は途中の後片付け（確保済みメモリの解放、ポインタのクリア、カウンタの巻き戻し）を
**実行せずに**脱出する。このため「メタデータと実体がずれた中途半端な状態」が生まれる。
両CVEとも、この「中途半端な状態を後続が信じる」という同じ根に由来する。

## CVE-2026-109618 — 未初期化メモリの利用

- 場所: `Zend/zend_hash.c` の `_zend_hash_str_add_or_update_i()`
  （`$_POST` 構築時などの文字列キー挿入）
- 流れ:
  1. 使用スロット数・要素数のカウンタを増やす
  2. キー文字列を確保する ← `memory_limit` 超過で失敗
  3. fatal エラーで挿入を中断（longjmp 脱出）
- ずれ: **カウンタは増えたまま**、そのバケットのキー・値は未初期化。
- 悪用面: リクエスト後の後片付けがカウンタを信じて全バケットを有効な値として走査。
  未初期化バケット＝前のメモリの残りを本物の値と解釈し、後片付けを意図しない呼び出しへ誘導できる。
- 分類: 「メタデータは有効と言うが中身は無効」という不整合バグ。未初期化メモリ読み取りが近い。
  同じパターンは他のコードパスにもあるとされ、ハッシュテーブルは一例にすぎない。
- パッチ(8.5.12): カウンタ順序はそのまま。エラー処理を変更。
  - ソフト上限：エラーを安全地点まで遅らせ、初期化を完了させてから処理
  - ハード上限：worker を即終了（`_exit(137)`）し、怪しい状態で後片付けを走らせない

## CVE-2026-109619 — use-after-free（解放済みメモリ参照）

- 原因: worker はリクエスト単位メモリを指すグローバルを持つ。
  fatal で longjmp 脱出するとメモリは解放されるが**ポインタがクリアされず残る**。
  次リクエストが古いポインタをたどって解放済み領域を読む。
- 確認された2経路:
  1. fatal エラーのバックトレース（PHP 8.5 のみ）：
     バックトレース状態がシャットダウンを生き延び、次リクエストの設定診断が再初期化前に読む。
  2. アップロード処理：アップロード中の fatal でセッション／デコーダ状態が残り、
     次のアップロードが初期化前に読む。**session upload progress**（デフォルト有効・
     `session_start()` 不要で動く）と結びつく。PHP-FPM では起動後に適切な操作も要る。
- パッチ: シャットダウン時にエラー・例外状態をクリアし、
  シリアライズ／セッション状態を早期処理が触る前に初期化し直す
  ＝ **リクエスト所有のグローバル状態を再利用前にリセット**する。

## 緩和策の限界（なぜパッチ必須か）

`session.upload_progress.enabled=0` は 109619 のアップロード経路を1つ塞ぐだけ。
109618 と、109619 のバックトレース経路は残る。だから設定変更では不十分で、
以下への更新が必要。

- 修正版: 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35
- 影響範囲: PHP 5.4〜8.5（8.1 以前は EOL のため上記への移行）

## この層をどう守るか（学びの一般化）

- 入力検証層（XSS/SQLi/CSRF）では防げない。アプリ側コードが正しくても、ランタイムが壊れる。
- 対策の主軸は「パッチ適用」＝エンドポイント／運用層の話に寄る。
- エラー／例外処理が通常フローを飛び越える言語機構（longjmp, 例外, panic/recover）は、
  **後片付けの一貫性**を壊しやすい。「エラー時に状態がどこまで進んだか」を疑う視点を持つ。
